# 設計

## なぜ ImGui のウィジェットを使わないのか

Dalamud プラグインの UI は ImGui で書くのが普通ですが、ImGui のウィジェットは
見た目の自由度が低いという制約があります。角丸や色はスタイル変数で変えられても、
「押したときに 1px 沈む」「ホバーで枠がじわっと金色に変わる」「チェックマークを
描き込むアニメーション」といった表現は、ImGui のウィジェットを使っている限り作れません。

そこで本ライブラリは、**ImGui をウィジェットライブラリとしては一切使いません**。
`ImGui.Button` や `ImGui.SliderInt` は呼ばず、次の 4 つの用途にだけ ImGui を使います。

| 用途 | 使う API |
|---|---|
| 描画面 | `ImDrawList`（`AddRectFilled` / `AddText` / `PathStroke` など） |
| 入力の取得 | `ImGui.GetIO()`、`ImGui.IsMouseDown` |
| クリッピングと Z 順 | `ImGui.Begin`（装飾をすべて無効にした透明な箱として） |
| フォーカス管理 | `ImGui.IsWindowFocused` / `SetWindowFocus` |

ウィンドウは `NoTitleBar | NoBackground | NoScrollbar | NoMove | NoResize` で開き、
タイトルバー・枠・リサイズグリップ・スクロールバー・全ウィジェットを自前で描きます。
位置と大きさもライブラリ側で持つため、移動もリサイズも自前の処理です。

### 例外: 文字入力

1 行/複数行のテキスト入力だけは、文字の編集そのものを ImGui の入力欄に任せています。
カーソル移動・範囲選択・クリップボード・**日本語 IME の変換**を自前で実装するのは
現実的でないためです。枠・地・フォーカスリングは自前で描き、ImGui 側は背景も枠も
透明にして重ねています。

同様に、ドロップダウンの一覧は `ImGui.BeginPopup` の上に自前描画しています。
「他のウィンドウより手前に出す」「外側をクリックしたら閉じる」という挙動だけを
借りるためで、中身の描画と選択判定はすべてライブラリ側です。

## 層構成

```
EUi (静的ファサード)
 ├── Fluent    宣言的なウィンドウ定義
 ├── Binding   属性からの設定画面生成
 ├── Widgets   ウィジェット本体と IWidgetPainter
 ├── Windowing EuWindow / EuWindowManager
 ├── Layout    レイアウトエンジンとコンテナ
 ├── Theming   デザイントークンとフォント
 ├── Render    描画プリミティブ (Painter / TextPainter / EuColor)
 └── Core      ID・矩形・入力・状態保持・アニメーション
```

下の層ほど汎用的で、上の層は下の層だけを使って組み立てられています。
**ライブラリ内部専用の描画手段や状態管理はありません。** 利用者が独自ウィジェットを
書くときも、ライブラリ自身と同じ `Painter` / `Interaction` / `WidgetStore` を使います。

## immediate mode での状態管理

ウィジェット自身はフレームをまたいで値を保持できないため、`EuId`（ラベルから
FNV-1a で作るハッシュ）を鍵にして `WidgetStore` に預けます。ホバーの遷移量、
押下の遷移量、折りたたみの開閉、スクロール位置などがここに入ります。

長く参照されなかった状態は一定フレームごとに掃除されます。

### フレームの進み方

利用側が「フレームの開始」を明示的に宣言しなくてよいように、公開 API はすべて
冒頭で `UiContext.EnsureFrame()` を呼びます。これは ImGui のフレーム番号を見て、
**1 フレームにつき 1 回だけ**更新処理を走らせます。どこから何度呼ばれても安全です。

## レイアウト

immediate mode では「全要素を見てから配置を決める」ことができません。
本ライブラリはこの制約に対して 3 つの方法を使い分けています。

1. **カーソル前進** — 縦積み・横並びの基本。要素を置くたびにカーソルが進む
2. **列の事前宣言** — 残り幅の配分が必要な行は `EUi.Row(120f, SizeSpec.Fill, 60f)` の
   ように列幅を先に宣言してもらう。これなら 1 パスで正確に配分できる
3. **前フレームの実測値** — カードの高さやラベル列の幅など、内容から決まる寸法は
   前フレームに測った値を使う。項目が増減した直後の 1 フレームだけずれるが、
   次のフレームで揃う

レイアウトスコープを閉じると、そのスコープが実際に消費した大きさを外側へ申告します。

### 生 ImGui との混在

領域を確保するたびに、ImGui 側のカーソル (`ImGui.SetCursorScreenPos`) も同じ位置へ
動かしています。これにより「EstellUtils で描いた続きに生の `ImGui.*` を呼ぶ」が
そのまま成立します。逆向き (生 ImGui が進めたカーソルへ合わせる) は
`EUi.SyncFromImGui()` を呼びます。

## アロケーションへの配慮

UI は毎フレーム実行されるので、GC を刺激しない書き方を選んでいます。

- レイアウトスコープはプールして使い回す
- 列の宣言は `params ReadOnlySpan<SizeSpec>` と `stackalloc`
- 数値の書式化は `TryFormat` + `stackalloc char[]`
- テキストの切り詰めはスレッド静的な作業バッファを使い回す
- 設定バインディングのアクセサは式木から一度コンパイルしてキャッシュする
  （毎フレームのリフレクション呼び出しとボクシングを避ける）

## 描画の省略とクリップ

`ImDrawList` 側のクリップ矩形は読み出しにくいため、ライブラリでも同じ範囲を並行して
追跡しています（`Painter.CurrentClip`）。これが 2 つの役割を果たします。

1. **描画の省略** — `Painter` と `TextPainter` の各メソッドは、対象がクリップ範囲と
   重ならなければ何も描きません。長い一覧をスクロールさせても、画面に映っている行だけが
   頂点を生成します。ラベルは計測すら省きます
2. **入力の整合** — クリップ範囲の外にあるウィジェットはホバーしません。
   スクロールで隠れた項目が、その下に見えている別のウィジェットと一緒に反応する、
   といったことが起きません

最前面レイヤーへ切り替えたとき（ツールチップや通知）はクリップを引き継ぎません。
スクロール領域の中から出した説明文が切り取られないようにするためです。

## 拡張のしかた

| やりたいこと | 方法 |
|---|---|
| 色や余白を変える | `Theme` を `Clone()` / `Derive()` してトークンを書き換える |
| ボタンの見た目を作り直す | `DefaultWidgetPainter` を継承して `DrawButton` だけ差し替える |
| 独自ウィジェットを作る | `EUi.Reserve` で矩形を取り、`Interaction.Behavior` で判定し、`Painter` で描く |
| トークンを増やす | `theme.CustomColors` / `theme.CustomMetrics` に自由に追加できる |

## 動作の重さを追う

immediate mode では毎フレーム全部を組み直すため、コストはほぼ「いくつ処理したか」で決まります。
`EUi.Stats` に 1 フレームぶんの内訳が入っています。

| 値 | 意味 |
|---|---|
| `Allocations` | 領域を確保した回数。おおよそのウィジェット数 |
| `Interactions` | 入力判定の回数 |
| `DrawCalls` / `Culled` | 描いた回数 / クリップ外で省いた回数 |
| `TextMeasures` / `TextCacheHitRate` | 文字を測った回数とキャッシュ率 |

デモの「動作確認」タブに表示しています。読み方は次のとおりです。

- **`Culled` が伸びている** — 見えていない部分をうまく飛ばせています
- **`TextCacheHitRate` が低い** — 毎フレーム別の文字列を組み立てている疑いがあります。
  `$"{value:F1} fps"` のような文字列は値が変わるたびに測り直しになります
- **`Allocations` が数百を超える** — 一覧を仮想化できないか検討してください

### 件数の多い一覧

高さが揃っているなら `EUi.VirtualList` を使うと、**件数に関係なく 1 フレームの仕事が一定**になります。

```csharp
EUi.VirtualList("items", this.items.Count, 24f, 300f, i => DrawRow(this.items[i]));
```

高さが項目ごとに違う場合は `EUi.IsRowVisible(height)` で 1 行ずつ間引きます。

```csharp
foreach (var item in items)
{
    if (!EUi.IsRowVisible(24f))
    {
        EUi.Reserve(SizeSpec.Fill, 24f);
        continue;
    }

    DrawRow(item);
}
```

### 滑らかさを保つ仕組み

- アニメーションは**指数減衰**なので、60fps でも 144fps でも同じ体感速度になります
- 目標に十分近づいたら**吸着**します。微小な差分が残り続けて再描画されることはありません
- `DeltaTime` は **20fps 相当で頭打ち**にしています。ゲームが一瞬止まったとき、
  止まっていた分がまとめて適用されてアニメーションが瞬間移動するのを防ぎます

`Motion.Enabled` を false にすると遷移が即座になります。軽くはなりますが、
上の仕組みがあるので、重さの対策としてまずここを切る必要はないはずです。

### 文字の計測

計測結果はフォントごとにキャッシュされます。フォントの識別子と大きさは
**フレームに一度だけ** ImGui へ問い合わせ、`PushFont` の出入りで取り直します。
項目の多い画面では、この問い合わせだけで数百回に達するためです。
